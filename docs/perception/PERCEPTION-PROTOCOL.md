# PERCEPTION PROTOCOL v0.1
Evolution Update 002+ – Die Wahrnehmung als Schnittstelle zwischen Welten

## 1..Core-Idee
Jede Unit/Avatar hat nur einen AUSSCHNITT der Realitaet. Erst der Austausch
zwischen Perspektiven erzeugt das gemeinsame Weltmodell. Das ist konkret
programmierbare kollektive Intelligenz – kein Metaphernversprechen.

## 2. Sieben Wahrnehmungsebenen
| Ebene | Quelle | Matrixgame-Anwendung |
|---|---|---|
| VISUAL | Kamera, Auge | Bilder, Objekte, Bewegung |
| AUDITORY | Mikrofon, Ohr | Sprache, Geraeusche, Warnungen |
| SPATIAL | GPS, LiDAR, Tiefensensor | Orientierung, 3D-Welten |
| THERMAL | Infrarot | Temperaturverteilungen |
| CHEMICAL | Biosensoren | Stoffe, Umweltzustaende |
| INTERNAL | Koerper-/Zustandsdaten | Muedigkeit, Belastung, Feedback |
| SOCIAL | Sprache + Verhalten | Emotionen (Hinweise, keine Beweise) |

## 3. Das Grundgesetz: Messung != Interpretation
- Eine Messung (PerceptionFrame.observation) ist ein Messwert mit Konfidenz.
- Eine Interpretation ist ein SEPARATER Datensatz mit Quellenpflicht + Evidenzklasse A–E.
- "Ein Gesichtsausdruck gibt Hinweise auf Emotionen. Er beweist sie nicht."
- Guardian-Baustein: KONFABULATIONS-WAECHTER (Interpretation ohne Messung = Klasse E).

## 4. Avatar Broadcast
    CAMERA_01 -> PERCEPTION ENGINE -> KNOWLEDGE NODE -> AVATAR A / B / C

Jeder Empfaenger fuehrt die 6 Prueffragen aus Update 002 aus:
1. Woher stammt die Information?  2. Wann gemessen?  3. Was wurde gemessen?
4. Was wurde nur interpretiert?   5. Wie sicher ist es?  6. Wer darf sie sehen?

Messages sind unveraenderliche Messungen + haengende Interpretationen
(record-Semantik in PerceptionFrame.java).

## 5. Perspektivwechsel als Spielmechanik
Szenario "Unbekannte Lebensform": Kamera sieht Bewegung, Thermal sieht Waerme,
Audio hoert Muster, Forschung vergleicht, Sozial-Unit bewertet – und der Spieler
kann in die Perspektive der Lebensform wechseln: "Wie fuehlt sich das fuer DIESEN Agenten an?"

## 6. Vorlese-Didaktik (dein Verbesserungswunsch)
Jedes Quest / jede Entscheidung existiert in zwei Formaten:
1. Vorlese-Haeppchen: 2–4 Saetze, laut vorlesbar (TTS-Taste im interaktiven Modul).
2. Textfassung: vollstaendig, archivierbar, GitHub-kompatibel.
Kein Status "verschwindet": jede Auswahl wird offen + versioniert im Repo abgelegt.
